# Sinclair ZX80 / ZX81

Sinclair's first two Z80 home computers: a 1 KB, ROM-BASIC machine with a
membrane keyboard that drives a television from a display file in RAM. zx84
emulates both models with their stock ROMs, the 16 KB RAM pack, five hi-res
graphics add-ons, software-generated hi-res on the ZX81, and a program-image
cassette model.

## Models

| Model | Year | RAM | ROM | Video | Sound | Storage | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ZX80 (`zx80`) | 1980 | 1 KB, or 16 KB with the RAM pack | 4 KB | Display file, 32×24 characters, monochrome | None | Program images via LOAD/SAVE trap | Programs load at 0x4000, no names; no NMI display driver |
| ZX81 (`zx81`) | 1981 | 1 KB, or 16 KB with the RAM pack | 8 KB | Display file, 32×24 characters, monochrome; software and add-on hi-res | None | Program images via LOAD/SAVE trap | Programs load at 0x4009 (VERSN) and carry a name; NMI-paced SLOW mode |

Both models share 64,584 T-states per frame (207 T × 312 lines) at 3,250,000 Hz.
The picture is a 256×192 active area inside a 32-pixel left/right and 24-pixel
top/bottom border (320×240 frame), black on white.

### ROM sets

| Model | Locale | ROM pages | Source |
| --- | --- | --- | --- |
| ZX80 | none | 1 (4 KB) | hosted (`sinclair/zx80.rom`) |
| ZX81 | none | 1 (8 KB) | hosted (`sinclair/zx81-v2.rom`) |
| ZX81 Memotech HRG board | — | 2 KB expansion ROM | fetched from the EightyOne repository on GitHub when the board is enabled |
| ZX81 QuickSilva HRG board | — | 2 KB expansion ROM | fetched from the EightyOne repository on GitHub when the board is enabled |

The system ROM can be replaced from the ROM pane (a single slot, labelled
`ROM`); there are no locale variants. Dropping a raw ROM image picks the model by
size: 4 KB → ZX80; 8 KB → ZX81, but only while a ZX80 or ZX81 is already the
current machine. Images are padded with 0xFF or truncated to the model's ROM
size.

## Built-in hardware

| Part | Models | Status | Notes |
| --- | --- | --- | --- |
| Z80 CPU | all | ✅ | Shared core [`src/cores/z80.ts`](../../src/cores/); no contention hooks |
| Memory decoding | all | ✅ | A15 is not decoded, so the lower 32 KB echoes in the upper 32 KB. ROM mirrors through 0x0000–0x3FFF; internal 1 KB RAM repeats through 0x4000–0x7FFF; a 16 KB pack is contiguous 0x4000–0x7FFF. ROM is read-only; reset clears RAM only |
| Display (ULA behaviour) | all | ◐ | Frame rendered from D_FILE (0x400C) using the character page in the I register, with inverse video from bit 7. Not a beam-accurate ULA: see Emulation features |
| Display opcode fetch | all | ✅ | An opcode fetch from the A15-high echo of a character byte reads as NOP; a 0x76 line end stays HALT |
| NMI display driver | ZX81 | ✅ | `OUT (0xFE)` enables and `OUT (0xFD)` disables a once-per-scanline NMI (SLOW mode) |
| A6-driven `/INT` | all | ✅ | The maskable interrupt fires when bit 6 of the last refresh address is clear, sampled after every instruction |
| Keyboard | all | ✅ | 8×5 active-low matrix read through any port; IN returns `0x60` ORed with the key bits |
| Cassette interface | all | ◐ | No waveform: the ROM's LOAD and SAVE routines are trapped and move program images directly (see Media formats) |

## Peripherals

All options are in the Hardware pane. Every change rebuilds the machine.

| Peripheral | Type | Models | Status | Notes |
| --- | --- | --- | --- | --- |
| 16 KB RAM pack | RAM | ZX80, ZX81 | ✅ | Checkbox "16KB RAM"; contiguous 0x4000–0x7FFF |
| UDG RAM (`udg`) | Character RAM | ZX81 | ✅ | Character-generator RAM at 0x3000–0x3FFF, 64-character set |
| UDG-128 (`udg128`) | Character RAM | ZX81 | ✅ | Same window; bit 7 of the character code becomes character-address bit 6 (128 characters, no inverse) |
| WRX hi-res (`wrx`) | Bitmap RAM | ZX81 | ✅ | Refresh-readable static RAM at 0x2000–0x3FFF; also captures WRX1K rows from stock RAM, including 1–31 byte wide rows |
| Memotech HRG (`memotech`) | Hi-res board | ZX81 | ✅ | 248×192; 2 KB ROM at 0x2000, 1 KB RAM overlay at 0x0000–0x03FF (writes always land in it; reads see it while bit 0 of I is set); mode selected by the high byte of an IN from port 0x5F (modes 2 and 3 show the hi-res image, 3 inverted) |
| QuickSilva HRG (`quicksilva`) | Hi-res board | ZX81 | ✅ | 256×192; 2 KB ROM at 0x2800, 6 KB framebuffer at 0xA000–0xB7FF; a read from 0x2000–0x3FFF turns the picture on, a write there turns it off |

**Combination rules:** the five ZX81 graphics boards are mutually exclusive;
selecting one clears the others. If more than one is requested together
(for example from saved settings) the priority is QuickSilva, Memotech, WRX,
UDG-128, UDG. They are not offered on the ZX80. The 16 KB RAM pack combines with
any of them.

## Media formats

Programs are the only media. Each model accepts only its own extensions and
refuses the other's. ZIP archives are unpacked and their contents routed
likewise. There is no tape deck, disk or snapshot service, and mounted programs
are not persisted across a reload.

| Extension | Kind | Device | Load | Save | Notes |
| --- | --- | --- | --- | --- | --- |
| `.o` | Program | ZX80 | ✅ | ✗ | RAM image from 0x4000 (the ZX80 SAVE format) |
| `.80` | Program | ZX80 | ✅ | ✗ | Treated identically to `.o` |
| `.p` | Program | ZX81 | ✅ | ✗ | RAM image from VERSN (0x4009) up to E_LINE |
| `.81` | Program | ZX81 | ✅ | ✗ | Treated identically to `.p` |
| `.p81` | Program | ZX81 | ✅ | ✗ | The leading name (up to 128 bytes, ending on a byte with bit 7 set) is stripped and used as the tape name |

Mounting a program resets the machine, writes the image into RAM, sets the CPU
registers (the ZX81 gets the stable post-LOAD state, including the nine VERSN-
prefix system variables a `.p` omits) and starts it, so it runs without typing
LOAD. If the ROM's LOAD is already waiting for a tape, the mounted program is
instead delivered to that LOAD, whatever name it asked for. A program larger than
the installed RAM is refused with "needs 16KB RAM".

**Tape shelf:** programs mounted or SAVEd in the session sit on an in-memory
shelf in mount order. `LOAD ""` reads the next program after the play position;
`LOAD "NAME"` winds forward, wrapping once, to the first matching name. The
ZX80 LOAD reads the next program regardless of name. SAVE records the image
(ZX81: with its name) on the shelf and shows a status message, but nothing is
written to a file. The trap applies only when the ROM contains the stock
LOAD/SAVE routines (checked by byte signature); a replaced ROM is never trapped.

**Save menu exports:** PNG screenshot, `.scr` screen dump (raw 256×192 1-bit
bitmap, 6,144 bytes), RAM `.bin` (internal RAM only, 1 KB or 16 KB, named
`ram-1k.bin` / `ram-16k.bin`).

## Emulation features

| Feature | Status | Notes |
| --- | --- | --- |
| Display-file video | ✅ | 32×24 characters rendered after each frame from D_FILE, honouring the I register's character page and inverse bit; collapsed (short) rows supported |
| ZX81 SLOW / FAST picture | ✅ | A frame shows the display file only if the CPU executed it that frame (always in SLOW; in FAST only while the ROM runs its display loop, e.g. awaiting a key or PAUSE). Otherwise the frame is blank |
| Software pseudo-hi-res (ZX81) | ✅ | Rows of 32 contiguous 4 T display fetches bracketed by program sync `OUT`s are captured at M1 time and drawn as a bitmap; also NMI-paced standard-font rows for HUD text, UDG and WRX rows |
| Fast cassette loading | ✅ | Direct transfer through the ROM LOAD/SAVE trap; there is no real-time tape |
| Border size | ✅ | None / small / normal crops of the 32×24 pixel border |
| Sound | — | None; the audio mixer is silenced |

## Known issues

None known.

## Not emulated

- **Cassette waveform.** LOAD and SAVE are intercepted at fixed ROM addresses and move program images directly; no pulses are generated or read, so loaders that bypass the ROM routines cannot load from tape, and SAVE never produces a file.
- **ZX Printer.** No printer port decoding; every IN returns keyboard data.
- **Joysticks and mice.** No input ports (`joystick: false`, no mouse types); keyboard only.
- **Sound.** Neither model has an audio path in zx84.
- **Chroma 81 and other ZXDB enhanced-graphics methods.** The catalog tag list names Chroma, but only software hi-res, UDG, UDG-128, WRX / HRG-ms, Memotech and QuickSilva are mapped to hardware; other tags remain catalog metadata.
- **Colour.** The picture is monochrome.

## Faithful quirks

- **A15 is not decoded.** The lower 32 KB echoes in the upper 32 KB, so code running from 0x8000 upward sees the display file as the ZX81 hardware does.
- **Internal 1 KB RAM repeats through 0x4000–0x7FFF.** Writes alias, as on a stock machine without the pack.
- **FAST mode blanks the picture while computing.** The ZX81 only produces a picture when the CPU executes the display file; tests cover both the displayed and blank cases.
- **Display fetches read as NOP.** An opcode fetch of a character byte from the A15-high echo returns NOP while a 0x76 line end remains HALT.
- **Interrupt timing follows refresh address bit 6.** A collapsed display row HALTs and idles until the A6-driven `/INT` arrives; the test pins the exact 191 T-state sequence.
