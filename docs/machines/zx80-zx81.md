# Sinclair ZX80 / ZX81

Sinclair's first two Z80 home computers: a 1 KB, ROM-BASIC machine with a
membrane keyboard that drives a television from a display file in RAM. zx84
emulates both models with their stock ROMs, the 16 KB RAM pack, five hi-res
graphics add-ons, software-generated hi-res on the ZX81, a pulse-level cassette
(with an instant LOAD/SAVE fast path), the ZON X-81 sound interface, the ZX
Printer and the Chroma 81 colour interface.

## Models

| Model | Year | RAM | ROM | Video | Sound | Storage | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ZX80 (`zx80`) | 1980 | 1 KB, or 16 KB with the RAM pack | 4 KB | Display file, 32×24 characters, monochrome | None (optional ZON X-81, VSYNC sound) | Cassette pulses; instant LOAD/SAVE trap | Programs load at 0x4000, no names; no NMI display driver |
| ZX81 (`zx81`) | 1981 | 1 KB, or 16 KB with the RAM pack | 8 KB | Display file, 32×24 characters, monochrome; software and add-on hi-res; optional Chroma 81 colour | None (optional ZON X-81, VSYNC sound) | Cassette pulses; instant LOAD/SAVE trap; optional ZX Printer | Programs load at 0x4009 (VERSN) and carry a name; NMI-paced SLOW mode |

Both models share 64,584 T-states per frame (207 T × 312 lines) at 3,250,000 Hz.
The picture is a 256×192 active area inside a 32-pixel left/right and 24-pixel
top/bottom border (320×240 frame), black on white.

### ROM sets

| Model | Locale | ROM pages | Source |
| --- | --- | --- | --- |
| ZX80 | none | 1 (4 KB) | hosted (`sinclair/zx80.rom`) |
| ZX81 | none | 1 (8 KB) | hosted (`sinclair/zx81-v2.rom`) |
| ZX81 Memotech HRG board | — | 2 KB expansion ROM | fetched from the EightyOne repository on GitHub when the board is enabled |
| ZX81 QuickSilva HRG board | — | 2 KB expansion ROM | fetched from the EightyOne repository on GitHub when the board is enabled |

The system ROM can be replaced from the ROM pane (a single slot, labelled
`ROM`); there are no locale variants. Dropping a raw ROM image picks the model by
size: 4 KB → ZX80; 8 KB → ZX81, but only while a ZX80 or ZX81 is already the
current machine. Images are padded with 0xFF or truncated to the model's ROM
size.

## Peripherals

All options are in the Hardware pane. Every change rebuilds the machine.

| Peripheral | Type | Models | Status | Notes |
| --- | --- | --- | --- | --- |
| 16 KB RAM pack | RAM | ZX80, ZX81 | ✅ | Checkbox "16KB RAM"; contiguous 0x4000–0x7FFF |
| UDG RAM (`udg`) | Character RAM | ZX81 | ✅ | Character-generator RAM at 0x3000–0x3FFF, 64-character set |
| UDG-128 (`udg128`) | Character RAM | ZX81 | ✅ | Same window; bit 7 of the character code becomes character-address bit 6 (128 characters, no inverse) |
| WRX hi-res (`wrx`) | Bitmap RAM | ZX81 | ✅ | Refresh-readable static RAM at 0x2000–0x3FFF; also captures WRX1K rows from stock RAM, including 1–31 byte wide rows |
| Memotech HRG (`memotech`) | Hi-res board | ZX81 | ✅ | 248×192; 2 KB ROM at 0x2000, 1 KB RAM overlay at 0x0000–0x03FF (writes always land in it; reads see it while bit 0 of I is set); mode selected by the high byte of an IN from port 0x5F (modes 2 and 3 show the hi-res image, 3 inverted) |
| QuickSilva HRG (`quicksilva`) | Hi-res board | ZX81 | ✅ | 256×192; 2 KB ROM at 0x2800, 6 KB framebuffer at 0xA000–0xB7FF; a read from 0x2000–0x3FFF turns the picture on, a write there turns it off |
| ZON X-81 (`zx8x-zonx`) | Sound | ZX80, ZX81 | ◐ | Bi-Pak ZON X-81, an AY-3-8912 on ports `0xCF` (select register) and `0x0F` (write data), decoded as A0–A3 high, A4 low, A7 choosing the function; no reads; clocked at the CPU clock / 2 (1.625 MHz) into one speaker (mono). The decode and clock are from the one published description of the original unit, which its own page says may be wrong in details; the later ZON X (A0–A4 decode) is not modelled |
| VSYNC sound (`zx8x-vsync-sound`) | Sound | ZX80, ZX81 | ◐ | The MIC / vertical-sync line mixed into the sound as a one-bit beeper (it is what SAVE sounds like, and the buzz programs make by pulsing sync). It is the tape-out line, not a documented speaker output, so it is off by default |
| ZX Printer (`zx81-zx-printer`) | Printer | ZX81 | ✅ | Port `0xFB` (A2 low): OUT bit 7 stylus, bit 2 motor (low runs), bit 1 slow; IN bit 0 encoder, bit 6 low when connected, bit 7 stylus at the paper's left edge; bits 0 and 7 latch until the next write. 256 dots, one row per 80 ms sweep (slow motor: twice that). The printout is shown in the Hardware pane and saved as `zx-printer.png`; `LPRINT`, `LLIST` and `COPY` from the real ROM print |
| Chroma 81 (`zx81-chroma81`) | Colour | ZX81 | ✅ | Control `OUT 0x7FEF` `%00EMIGRB` (E enable, M mode, IGRB border), `IN 0x7FEF` bit 5 low; 16 KB RAM at 0xC000–0xFFFF. Character code mode: colour byte `%IGRBigrb` (paper high, ink low) per character line at `0xC000 + 8 × code` (inverse characters from 0xC200); attribute file mode: one byte per display-file byte at `address \| 0xC000`. Bright is 100%, dull 69% |

The ZX Printer and Chroma 81 are ZX81 options; the ZON X-81 and VSYNC sound
are offered on both models. They combine with each other and with any graphics
board. With the Chroma 81 fitted its RAM replaces the 0xC000–0xFFFF echo for
data reads and writes (a display opcode fetch there still sees the display file).

**Combination rules:** the five ZX81 graphics boards are mutually exclusive;
selecting one clears the others. If more than one is requested together
(for example from saved settings) the priority is QuickSilva, Memotech, WRX,
UDG-128, UDG. They are not offered on the ZX80. The 16 KB RAM pack combines with
any of them.

## Media formats

Cassettes (as programs or recordings) and zx84's own snapshots are the media.
Each model accepts only its own program extensions and refuses the other's;
`.tzx` and `.wav` recordings are accepted by both. ZIP archives are unpacked
and their contents routed likewise. There is no disk service. A tape in the
deck persists across a reload like the other deck machines'.

| Extension | Kind | Device | Load | Save | Notes |
| --- | --- | --- | --- | --- | --- |
| `.o` | Program | ZX80 | ✅ | ✅ | RAM image from 0x4000 (the ZX80 SAVE format). Save is the most recent SAVE, named `zx80.o` |
| `.80` | Program | ZX80 | ✅ | ✗ | Treated identically to `.o` |
| `.p` | Program | ZX81 | ✅ | ✅ | RAM image from VERSN (0x4009) up to E_LINE. Save is the most recent SAVE, named after its program (`NAME.p`, with characters a filename cannot hold replaced by `_`) |
| `.81` | Program | ZX81 | ✅ | ✗ | Treated identically to `.p` |
| `.p81` | Program | ZX81 | ✅ | ✗ | The leading name (up to 128 bytes, ending on a byte with bit 7 set) is stripped and used as the tape name |
| `.tzx` | Tape recording | Both | ✅ | ✗ | ZX81 tapes are stored as block `0x19` (generalized data) and are played as the pulses it describes; any other pulse blocks play too. The programs on the tape are found by decoding its pulses |
| `.wav` | Tape recording | Both | ✅ | ✗ | Thresholded into pulses; either polarity (the gaps between bits are made low, as the ROM expects) |
| `.zx8xstate` | Snapshot | Machine | ✅ | ✅ | zx84's own exact save state, either model (see below) |

**Cassette signal.** A `.p`, `.81`, `.p81` or `.o` is turned into the documented
pulse train and put in the deck: each bit is a burst of 4 (zero) or 9 (one)
pulses of about 150 µs (530 T / 520 T halves at the TZX 3.5 MHz reference)
followed by a 4689 T (1.34 ms) gap, bytes most significant bit first, the ZX81
file being the name (last character with bit 7 set) then RAM from VERSN
(0x4009) up to E_LINE, the ZX80 file RAM from 0x4000 up to E_LINE; there is no
leader or checksum, and half a second of silence precedes the program. The
deck's level is bit 7 of every keyboard-port read, so the real ROM LOAD, and any
custom loader reading port `0xFE`, load from it. The ROM's LOAD starts the deck
itself when a tape is inserted and nothing else is playing (unless the user
stopped it); the Tape pane's play, pause, stop, rewind and block controls
apply, and its list shows each program as a `LOAD "NAME"` line. The deck's
pulses can drive the loading turbo.

**Fast ROM loading** (Tape pane option, on by default) keeps the instant path:
the ROM's LOAD and SAVE are trapped at fixed addresses and move program images
directly. LOAD reads the next program from the tape in the deck (`LOAD ""`)
or, winding forward and wrapping once, the first matching name (`LOAD "NAME"`);
the ZX80 LOAD reads the next program regardless of name. The programs are those
found by decoding the tape's pulses, so a TZX or WAV with several programs on it
is read one after another. With the option off, LOAD and SAVE run the real ROM
routines in real time. The trap applies only when the ROM contains the stock
LOAD/SAVE routines (checked by byte signature); a replaced ROM is never trapped.

Mounting a program image with the trap on also loads it straight into RAM and
starts it (resetting the machine, writing the image, setting the CPU registers
— the ZX81 gets the stable post-LOAD state, including the nine VERSN-prefix
system variables a `.p` omits), so it runs without typing LOAD; with it off, the
tape is just inserted. A tape inserted while the ROM's LOAD is already waiting is
played into that LOAD (with the trap on its first program is delivered whatever
name LOAD asked for). A program larger than the installed RAM is refused with
"needs 16KB RAM".

**SAVE.** With the trap on SAVE records the image directly (ZX81: with its name)
and shows a status message. With it off the ROM writes pulses on MIC, which are
captured and decoded. Either way the most recent SAVE since reset is kept for
the Save menu's **Saved tape** entry, which downloads it as the `.p`/`.o` image
LOAD reads back. Only the latest SAVE is offered; programs SAVEd with the trap
on also sit on an in-memory shelf that a later LOAD reads when the deck has
nothing to give.

**Snapshots.** `.zx8xstate` is zx84's native save state, in the same container
as the Atari's `.a8state` (magic `ZX8X`, a CRC-32 and length checked before the
machine is touched, deflated when saved): the Z80 with its hidden MEMPTR/Q
latches and interrupt delays, all RAM including the graphics boards' RAM, the
ZX81's NMI generator, the Memotech/QuickSilva HRG mode latches, the vertical-sync
line, the state of whichever of the ZON X-81 (the AY and its generators
mid-cycle), ZX Printer (motor, stylus, latches, belt position, the printout so
far) and Chroma 81 (control register and RAM) are fitted, the software
hi-res capture buffers that span frames and the beam's frame grid, so a restore
carries on cycle for cycle. The header records the model and the CRCs of the
ROM and the HRG board's ROM (a different ROM is loaded anyway, with a warning).
A state saved with a different RAM size or graphics board, or with an add-on
this machine does not have, is refused, naming what to change in the Hardware pane; a state for the other model asks to switch
to it. A state is taken between frames (a frame a debugger stop left open is run
to its end first). The same state backs browser-refresh resume. The cassette in the
deck, the tape shelf and the MIC recording are not part of the state (a restore
leaves the deck stopped where it is).

**Save menu exports:** Snapshot `.zx8xstate`, Saved tape (the most recent SAVE as `.p` / `.o`), PNG screenshot, `.scr` screen dump (raw 256×192 1-bit
bitmap, 6,144 bytes), RAM `.bin` (internal RAM only, 1 KB or 16 KB, named
`ram-1k.bin` / `ram-16k.bin`).

## Known issues

None known.

## Not emulated

- **Joysticks and mice.** No input ports (`joystick: false`, no mouse types); keyboard only.
- **Other ZXDB enhanced-graphics methods, and library launch of the Chroma 81.** Software hi-res, UDG, UDG-128, WRX / HRG-ms, Memotech and QuickSilva are mapped to hardware, and the Chroma 81 is a manual Hardware-pane option, but the library does not enable it for tagged titles; other tags remain catalog metadata. The Chroma 81's Quicksilva character-board emulation, its 8 KB WRX RAM, RS-232 port and WRX refresh reads of its colour RAM are not modelled.
- **Chroma 81 border without colour.** The border colour applies only while the colour-enable bit is set; the Technical Description does not say what a border written with colour disabled looks like, and zx84 shows the normal white.
- **ZX Printer details.** A timing model of the documented interface (an encoder pulse per dot position, one sweep per row); belt speed variation, paper-out and electrical faults are not modelled, and it is not offered on the ZX80 (whose ROM has no printer commands).
- **ZON X-81 variants.** Only the original unit's documented decode is modelled (see Peripherals); the later ZON X's wider decode and the Spectrum adapter are not.
- **Tape: unusual pulse timings.** The decoder reads pulses up to 600 µs as bit pulses and gaps longer than that as the space between bits; recordings with very different widths decode only within that, and the EAR line has no analogue or hysteresis model beyond the WAVE threshold.
- **ZX80 tape against the real ROM.** The ZX80 path (pulses, MIC capture, trap) shares the ZX81's encoding and is tested with a synthetic loader and trap ROM; the real ZX80 ROM is not available to the tests here, so only the ZX81 ROM's LOAD and SAVE are verified end to end.
- **Snapshots: the cassette, the tape shelf, and community formats.** `.zx8xstate` restores the machine exactly but not the cassette or the session's tape shelf. Other emulators' ZX81 snapshot formats (EightyOne `.z81`, etc.) are not loaded.

## Faithful quirks

- **A15 is not decoded.** The lower 32 KB echoes in the upper 32 KB, so code running from 0x8000 upward sees the display file as the ZX81 hardware does.
- **Internal 1 KB RAM repeats through 0x4000–0x7FFF.** Writes alias, as on a stock machine without the pack.
- **FAST mode blanks the picture while computing.** The ZX81 only produces a picture when the CPU executes the display file; tests cover both the displayed and blank cases.
- **Display fetches read as NOP.** An opcode fetch of a character byte from the A15-high echo returns NOP while a 0x76 line end remains HALT.
- **Interrupt timing follows refresh address bit 6.** A collapsed display row HALTs and idles until the A6-driven `/INT` arrives; the test pins the exact 191 T-state sequence.
